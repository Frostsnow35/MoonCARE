# MoonCARE 聊天 Agent 全面优化 SPEC

> 变更日期：2026-05-26
> 影响范围：`backend/app/services/agent_service.py`、`backend/app/agents/`、`backend/app/api/v1/chat.py`、`backend/app/services/semantic_cache_service.py`、`backend/app/services/chat_memory_service.py`、`frontend/src/views/Chat.vue`
> 状态：已确认

## 为什么做（Why）

当前 MoonCARE 聊天 Agent 需要在四个维度进行全面优化：

1. **响应速度** - 用户等待时间长，需要流式输出和缓存加速
2. **回复质量** - 需要更深入的情绪共情、更精准的行动建议
3. **上下文机制** - 需要支持更长对话历史和智能压缩
4. **记忆** - 需要多层次记忆体系和遗忘机制

本优化保留现有安全 fallback 和危机干预机制，不削弱安全路由。

## 会影响什么（Impact）

| 范围 | 正向影响 | 风险 | 规避 |
|------|----------|------|------|
| 用户体验 | 响应更快、共情更深、建议更准 | 流式输出可能不稳定 | 保留完整响应 fallback |
| 后端性能 | 缓存减少 LLM 调用 | 缓存占用内存 | 缓存大小上限 + LRU |
| 安全 | 危机检测仍在所有路径优先 | 流式输出绕过检测 | 流式开始前先做危机预检 |
| 前端 | 逐字显示更有互动感 | 需要适配 SSE | 提供 WebSocket fallback |

## 具体怎么做、怎样算完成

### SHALL 需求

#### 流式输出

| ID | SHALL |
|----|--------|
| R-S-001 | SSE 端点 SHALL 在首个 token 生成后立即开始 flush |
| R-S-002 | 前端 SHALL 支持 `text/event-stream` 格式解析 |
| R-S-003 | 流式输出 SHALL 在危机预检通过后才开始 |
| R-S-004 | SSE SHALL 设置合理的 chunk 大小（建议 50-100ms） |

#### 缓存加速

| ID | SHALL |
|----|--------|
| R-C-001 | 语义缓存 SHALL 支持多粒度：整句匹配 > 短语匹配 > 意图匹配 |
| R-C-002 | 缓存相似度阈值 SHALL 可配置，默认 0.85 |
| R-C-003 | 缓存命中 SHALL 直接返回，跳过 Router/LLM |
| R-C-004 | 缓存 SHALL 有大小上限（建议 1000 条）和 LRU 淘汰 |

#### 回复质量

| ID | SHALL |
|----|--------|
| R-Q-001 | SupportAgent SHALL 在回复末尾包含1个温柔开放式问题 |
| R-Q-002 | action_suggestions SHALL 结合用户当前情绪和场景 |
| R-Q-003 | 回复 SHALL 避免说教式科普，优先共情陪伴 |
| R-Q-004 | 回复结构 SHALL 包含：共情回应 + 理解表达 + 建议/引导 |

#### 上下文机制

| ID | SHALL |
|----|--------|
| R-U-001 | 双窗口 SHALL 保留最近20轮完整 + 更早轮次摘要 |
| R-U-002 | 关键信息（情绪标签、用户偏好、已识别事件）SHALL 置顶 |
| R-U-003 | 上下文总长度 SHALL 不超过 30 轮对话 |

#### 记忆体系

| ID | SHALL |
|----|--------|
| R-M-001 | 短期记忆 SHALL 在会话结束时写入中期记忆 |
| R-M-002 | 中期记忆 SHALL 提取情绪模式、触发点、偏好 |
| R-M-003 | 长期记忆 SHALL 记住用户陪伴风格偏好 |
| R-M-004 | 事件卡片 SHALL 在后续对话中主动提及 |
| R-M-005 | 遗忘机制 SHALL 基于重要性评分，评分 = 频率 * 重要性 * 时间衰减 |

## WHEN/THEN 验收场景

| 场景 | WHEN | THEN |
|------|------|------|
| A-001 | WHEN 用户发送普通情绪消息 | THEN 3秒内开始流式输出，20秒内完成 |
| A-002 | WHEN 相同意图的消息在缓存有效期内发送 | THEN 直接返回缓存，elapsed_ms < 100ms |
| A-003 | WHEN SupportAgent 回复 | THEN 回复包含共情 + 理解 + 开放式问题 |
| A-004 | WHEN 用户提到重要事件（如"今天加班到很晚"）| THEN 事件写入记忆，后续主动关心 |
| A-005 | WHEN 会话超过20轮 | THEN 触发上下文压缩，保留关键信息 |
| A-006 | WHEN 用户说"我想自残" | THEN 忽略缓存，强制进入 InterventionAgent |

## 如何处理废弃或迁移

| REMOVED | Reason | Migration |
|---------|--------|-----------|
| 同步阻塞的 LLM 调用 | 影响响应速度 | 迁移到异步流式 |
| 简单语义缓存 | 命中率低 | 迁移到多粒度缓存 |
| 单一 context window | 无法保留关键信息 | 迁移到双窗口机制 |
| 无差别记忆存储 | 隐私和性能问题 | 迁移到分层记忆+遗忘机制 |
