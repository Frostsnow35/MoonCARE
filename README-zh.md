# MoonCARE 她语

**女性经前情绪陪伴与健康护航**

MoonCARE 是一款专为女性设计的智能情绪健康应用，通过自然对话了解你的经前状态，提供温暖的情感支持与轻量的健康指导。

---

## 功能特性

### 1. AI 情绪对话
**描述**：基于多 Agent 路由系统的智能对话引擎，感知用户情绪状态，提供个性化的情感陪伴。

**用户收益**：在任何时候打开应用，都能获得理解与回应。AI 不仅能承接情绪表达，还会自然地了解你的身体状态和生活情境。

**使用场景**：
- 经前情绪波动、莫名烦躁时
- 想要倾诉但不想打扰他人时
- 深夜独处需要情感支持时

---

### 2. 经前状态了解
**描述**：通过自然聊天收集经前综合征（PMS）相关信号，生成仅供参考的周期状态小结。

**用户收益**：在不进行任何"测试"或"问卷"的情况下，系统会通过对话自然了解你的状态，生成可回看的状态小结，帮助你更好地认识自己的情绪周期。

**使用场景**：
- 想了解自己经前综合征的规律
- 想知道最近的情绪低落是否与周期有关
- 需要对自己的状态有更清晰的了解

---

### 3. 月经周期管理
**描述**：记录并预测月经周期，追踪经期、排卵期、黄体期等不同阶段。

**用户收益**：告别手动计算，智能预测帮助提前准备。直观的阶段展示让你了解当前处于哪个生理时期，合理安排生活和工作。

**使用场景**：
- 记录月经来潮日期
- 预测下次经期
- 了解自己处于哪个周期阶段

---

### 4. 情绪日记
**描述**：每日情绪记录与回顾，支持文字与情绪标签，记录身体症状与生活事件。

**用户收益**：通过持续的记录，发现情绪变化的规律与诱因。回顾历史日记时，能看到自己情绪的起伏轨迹。

**使用场景**：
- 每天睡前回看今日情绪
- 记录身体症状（如头痛、腹痛）
- 标记影响情绪的生活事件

---

### 5. 音乐疗愈
**描述**：根据你的情绪状态和周期阶段，推荐适合的音乐播放列表。

**用户收益**：无需选择困难，系统根据你的状态推荐合适的疗愈音乐。在情绪低落时获得恰当的音乐支持。

**使用场景**：
- 睡前放松时
- 经期不适想要舒缓
- 工作压力大需要减压

---

### 6. 呼吸引导
**描述**：结构化的呼吸练习，帮助缓解焦虑与身体紧张。

**用户收益**：通过科学的呼吸节奏，缓解即时的身体紧张和情绪焦虑。随时可用的快速放松工具。

**使用场景**：
- 感到焦虑或紧张时
- 经期腹痛想要缓解
- 睡前想要放松入睡

---

### 7. 波动曲线
**描述**：可视化的情绪与周期波动曲线，展示身心状态的变化趋势。

**用户收益**：直观地看到自己的情绪周期规律，更好地规划重要日程和生活节奏。

**使用场景**：
- 回顾一周/一月的情绪变化
- 分析周期与情绪的关系
- 为重要事项选择最佳时间

---

### 8. 个人中心
****：**描述**：个人资料管理、应用设置、数据管理。

**用户收益**：管理自己的账号信息，设置通知偏好，导出或删除个人数据，保护隐私安全。

**使用场景**：
- 修改昵称和头像
- 设置提醒通知
- 导出或删除个人数据

## 快速开始

### 环境要求

| 工具 | 版本要求 |
|------|----------|
| Python | 3.10+ |
| Node.js | 20+ |
| npm | 10+ |
| Docker（可选） | 24+ |

### 本地开发启动

**方式一：一键启动**

```bash
# 克隆项目后，在根目录执行
npm run setup    # 安装依赖、复制环境配置文件
npm run dev      # 同时启动前端和后端
```

**方式二：手动启动**

```bash
# 终端1：启动后端
cd backend
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000

# 终端2：启动前端
cd frontend
npm install
npm run dev
```

启动后访问：

| 服务 | 地址 |
|------|------|
| 前端 | http://localhost:3000 |
| 后端 | http://localhost:8000 |
| API 文档 | http://localhost:8000/docs |

### Docker 部署

**1. 准备环境变量文件**

```bash
cp .env.example .env
```

编辑 `.env` 文件，配置以下必填项：

```env
# 数据库密码（必填）
DB_PASSWORD=your_strong_password

# JWT 密钥（必填）
SECRET_KEY=your_long_random_secret_key

# AI Provider 配置（至少填写一个）
NVIDIA_API_KEY=your_nvidia_api_key
# 或
ZAI_API_KEY=your_zai_api_key
# 或
OPENAI_API_KEY=your_openai_api_key
```

**2. 构建并启动**

```bash
# 构建镜像
docker compose build

# 启动服务
docker compose up -d
```

**3. 验证服务**

```bash
# 检查服务状态
docker compose ps

# 查看应用日志
docker compose logs -f app

# 检查健康状态
curl http://localhost:8000/healthz
```

**4. 停止服务**

```bash
docker compose down
```

如需清除数据：

```bash
docker compose down -v
```

## 配置指南

### 前端环境变量

创建 `frontend/.env`：

| 变量名 | 说明 | 默认值 |
|--------|------|--------|
| `VITE_API_BASE_URL` | 后端 API 地址 | http://localhost:8000/api/v1 |

### 后端环境变量

创建 `backend/.env`：

| 变量名 | 说明 | 默认值 |
|--------|------|--------|
| `DATABASE_URL` | 数据库连接地址 | sqlite:///./healthai.db |
| `SECRET_KEY` | JWT 签名密钥 | -（必填） |
| `DEBUG` | 调试模式 | true |
| `LLM_PROVIDER` | AI Provider | nvidia |

### AI Provider 配置

| Provider | 必填环境变量 | 说明 |
|----------|-------------|------|
| NVIDIA | `NVIDIA_API_KEY`, `NVIDIA_BASE_URL`, `NVIDIA_MODEL_NAME` | 使用 NVIDIA NIM |
| Z.AI (GLM) | `ZAI_API_KEY`, `ZAI_BASE_URL`, `ZAI_MODEL_NAME` | 智谱 GLM 系列 |
| OpenAI | `OPENAI_API_KEY`, `OPENAI_BASE_URL`, `MODEL_NAME` | OpenAI 兼容接口 |
| vLLM | `VLLM_BASE_URL`, `VLLM_API_KEY`, `VLLM_MODEL_NAME` | 本地 vLLM 服务 |
| Accelerated | `ACCELERATED_LLM_BASE_URL`, `ACCELERATED_LLM_API_KEY`, `ACCELERATED_LLM_MODEL_NAME` | 加速推理服务 |

### LLM 超时配置

| 变量名 | 说明 | 默认值（秒） |
|--------|------|--------------|
| `LLM_REQUEST_TIMEOUT_SECONDS` | 请求总超时 | 45 |
| `LLM_CONNECT_TIMEOUT_SECONDS` | 连接超时 | 10 |
| `CHAT_AGENT_REPLY_TIMEOUT_SECONDS` | Agent 回复超时 | 45 |

## 隐私与安全

### 数据说明
- 聊天记录、日记、周期数据仅存储在你自己部署的服务器或本地
- 所有用户数据默认本地存储，不上传到任何第三方
- `DEBUG=false` 时使用生产级安全策略

### 危机干预
- 系统内置危机关键词检测
- 发现自杀、自残等高风险表达时，立即进入安全干预流程
- 提供全国心理援助热线等资源信息

### 安全建议
- 生产部署务必设置强密码和 JWT 密钥
- 不要将 `.env` 文件提交到代码仓库
- 定期更新 AI Provider 的 API Key

## AI 相关问题

**Q: AI 回复很慢或超时怎么办？**
A: 检查网络连接和 AI Provider 状态。可在 `.env` 中调整 `LLM_REQUEST_TIMEOUT_SECONDS` 值。若持续超时，可能是 API 限额或服务端问题。

**Q: 如何切换不同的 AI 模型？**
A: 修改后端 `.env` 中的 `LLM_PROVIDER` 和对应的 API Key。支持的 Provider 包括：NVIDIA、Z.AI (GLM)、OpenAI、vLLM、Accelerated。

**Q: 本地是否可以运行 AI 模型？**
A: 可以。通过 vLLM 或其他 OpenAI 兼容推理服务部署本地模型，在 `.env` 中配置 `VLLM_BASE_URL` 和 `VLLM_MODEL_NAME`。Windows 下 vLLM 需要 GPU 支持。

**Q: AI 回复质量不稳定怎么办？**
A: 可尝试：1）更换 AI Provider；2）调整超时配置；3）确保 API Key 额度充足；4）检查提示词配置。

**Q: 是否可以离线使用？**
A: 当前版本需要网络连接调用 AI 服务。完全离线模式在规划中。

## 常见问题

**Q: 如何修改端口？**
A: 本地开发修改 `package.json` 中的端口；Docker 部署修改 `.env` 中的 `APP_PORT`。

**Q: 如何重置数据库？**
A: 删除 `backend/healthai.db`（SQLite）或执行数据库迁移回滚（PostgreSQL）。

**Q: 前端构建失败怎么办？**
A: 检查 Node.js 版本（需 20+），清理缓存 `rm -rf node_modules package-lock.json && npm install`。

**Q: Docker 部署时数据库连接失败？**
A: 确保 `.env` 中 `DB_PASSWORD` 已设置，且 `docker-compose.yml` 中 postgres 服务已就绪。等待 healthcheck 通过后再访问应用。
